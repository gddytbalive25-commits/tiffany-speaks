# Tiffany Speaks — Delivery Outcomes

- [x] **Call Audio → Sign (approved MVP):** User can put a call on speaker and start microphone-based speech-to-text where supported by the browser; transcript and simple ASL discussion cues display Time → topic → comment scaffolding, raised-brow yes/no-question cues, furrowed-brow wh-question cues, and head-shake negation cues. Clearly state this is not validated ASL translation; the supplied portrait is not an animated signing avatar.
- [x] **Your Sign → Speech (approved MVP):** Camera preview is permission-based; user can manually type/select the intended phrase, the screen shows “Caller hears this,” and device text-to-speech speaks it where available. Clearly state that camera preview is not visual sign recognition and caller-call audio routing depends on the phone/device.
- [x] **Training Mode (approved MVP):** User records a camera clip, labels it, reviews/deletes it in the local library; explain that the local clips do not train a model and stay in browser storage on this device.
- [x] **Pre-recorded Sign Library (approved MVP):** Searchable starter/Plus catalog metadata works offline; the entries are English gloss labels only, with no invented ASL definitions, movement instructions, or sign footage.
- [x] **Polished Mobile UI:** Warm, modern accessible mobile-first design based on the prototype; Tiffany’s supplied photo is prominent; speakerphone and volume guidance, permissions/setup help, and Call, Sign, Train, and Library navigation are included.
- [x] **PWA:** App-owned installable manifest and icons; production service worker caches the UI, portrait, icons, and bundled gloss catalog where possible. The interface and README explain that speech recognition, synthesis voices, camera, and payments depend on device, browser, and connectivity; include iOS Add-to-Home-Screen guidance.
- [x] **Monetization foundation:** Stripe test integration, server-side one-time/subscription Checkout and price-ID readiness flags, durable guest session/order/entitlement records, raw-body webhook signature verification, event idempotency, free clip cap, Plus-gated features, purchase history, and a product/pricing page are implemented. Never grant entitlements from a browser return URL.
- [x] **Deliverables:** React + TypeScript source, Node/Express server, production Dockerfile, PWA files, pinned package manager/lockfile, and setup/deployment README are included; application code does not claim absent visual sign recognition or avatar signing.
- [ ] **Real ASL library and avatar signing:** Add licensed, ASL-reviewed sign videos and a signing/avatar sequence pipeline before claiming signed output; user-provided licensed media/model is still needed.
- [ ] **Visual ASL recognition:** Add and validate a real recognition model/dataset before claiming the camera understands signs; personal clips are not model training data.
- [ ] **Turn on Checkout and production sales:** User must select actual product prices, configure one-time and/or subscription Price IDs, claim the Stripe account, decide purchase/legal/support policies, set a billing-record retention and deletion-request policy plus customer-facing privacy/terms, provide live credentials through platform integration, and validate live webhook fulfillment before enabling sales. The connected Stripe account is currently test-only and both Price IDs are unset, so Checkout is disabled. The current MVP does not include account deletion or automated retention expiry.
- [ ] **Custom domain and public release:** Map `gooddaytobealive.com` and publish/deploy only after the owner’s pricing, privacy/terms, support, and live-payment choices are complete. The project includes a container deployment declaration and production build, but no public release is claimed.
